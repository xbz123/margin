# 网络代理与代理错误显示（2026-11-24 至 11-26）

用户的朋友在国内测试时，发现软件的流量默认不走代理，用户因此要求增加代理选项。代理功能在独立会话的 `codex/network-proxy` 分支上实现：实现和测试由 Claude 子代理完成，并在开发版上做了真机检查。主线程把它合并进 `codex/margin-unified`，跑公开 CI，出测试包，并在 Windows 安装版上实测。出站细节以 [OUTBOUND · Network proxy](../../OUTBOUND.md#network-proxy) 为准，产品条款见 [产品 Spec · 网络与代理](../../../product.md#network-proxy)。

## Windows 真机结果（`F:\margin\temp`，用户真实配置）

测试用的代理都是在本机临时起的：一个只记日志、负责转发 CONNECT 的代理，一个只回 407 的代理，另外用一个没有程序监听的端口模拟连不上。全程没有输入任何代理密码。

| 测试包 | 场景 | 结果 |
| --- | --- | --- |
| test.23 | 默认“跟随系统” | 设置里有“网络与代理”页，打字提问直连成功 |
| test.23 | 手动 HTTP 代理，代理正常 | 回答成功，代理日志记到 `CONNECT generativelanguage.googleapis.com:443` |
| test.23 | 手动代理，端口没有程序监听 | 显示英文原文 `[Error: The proxy server could not be reached.]`，没有改成直连 |
| test.23 | 代理要求认证 | 显示英文原文 `[Error: The proxy server requires authentication.]`，代理日志记到 407 |
| test.24 | 打字提问，代理连不上 / 要求认证 | `[错误：无法连接代理服务器。]` / `[错误：代理服务器需要用户名和密码。]` |
| test.24 | What to answer，代理连不上 | `❌ 错误（what_to_say）：无法连接代理服务器。` |
| test.24 | 笔试模式：Ctrl+H 截图后提交，代理连不上 / 要求认证 | `[错误：无法连接代理服务器。]` / `[错误：代理服务器需要用户名和密码。]` |
| test.24 | 笔试模式：在失败的回答上点“重试” | `❌ 错误：代理服务器需要用户名和密码。` |

每轮测完都把代理设置恢复成测试前的“跟随系统”（与测试前保存的值逐字段一致）；笔试模式恢复成关闭，删掉测试截图，关掉测试代理，再打字提问一次，确认直连正常。测试没有在历史里新建会议。

## 未验证

- 用户的朋友在国内通过 Clash 等工具的真实使用（系统代理或 TUN 模式下应无需填写）。
- 带用户名和密码的代理、SOCKS5 和 HTTPS 协议的代理；这些只有自动化测试覆盖。
- 实时转写 WebSocket 经过代理。
- 笔试定时自动截图出错时的显示：需要开始一次会议，用户 2026-11-27 决定不测。它和手动截图使用同一个错误显示函数。
- 英文界面，以及设置页“保存并测试”的错误翻译（测试会保存模型设置，所以没有点）。
- macOS 安装包没有做真机测试。

## 已知的剩余问题

- IPC 包装文字 “Error invoking remote method …” 仍是英文。
- 已经显示出来的错误，切换界面语言后不会重新翻译。
- 语音服务卡片的详情里显示的是原始错误文字。
