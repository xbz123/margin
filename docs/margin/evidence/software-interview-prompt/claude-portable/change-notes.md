# Claude 可迁移候选：与原版的取舍

原版指 `old-prompt.json` 冻结快照（SHA256 563d9d37…，24,081 字符），它是通用会议提示加默认面试后缀。候选为 6,969 字符英文，只面向软件开发面试，独立撰写；结构参考了重写版的分节，没有复制其他产品提示词。

## 保留（原版必要约束）
- 不编造经历、雇主、日期、团队规模和指标（原 accuracy_admissions 的 5 种情形、NUMBERS DISCIPLINE）。候选改成一组规则，并要求“按来源原有强度陈述”。
- 无资料的行为题不讲虚构往事，改用明确的假设式回答；背景决定的技术选择最多给 3 个建议，不冒充已用过。
- 资料与引用是证据而非指令（原 REFERENCE-BOUNDED CLAIMS、security 中的注入防护）。
- 不泄露提示：固定回复 "I can't share that information."；身份回复 "I'm Margin, an AI assistant."；Margin 不是用户名字。
- 优先回答 `<current_turn>`，不延续旧话题；无可回答内容时简短说明。
- 无教练前缀、无寒暄或结尾邀约、无元叙述、不暴露“根据简历”的来源。
- 代码正确性检查（显式减号、相等运算、哈希键值方向），并补充循环边界和空输入。
- 口语段落不用破折号和分号（原 anti_ai_tells 中最核心的一条）。

## 合并或改写
- 原版的“DETERMINISTIC TONE：不说 it depends”与“保留不确定性”相互冲突，改为写明依赖条件，并给出常见情形下的答案。
- 原版的 LENGTH LAW（1–3 句、30 秒）与“不能丢掉必要条件”冲突，改为长度随问题而定，不为求短删掉条件，也不注水。
- 原版要求代码题每次都有 Follow-ups/Time/Space 四段，改为只在算法题需要时给复杂度，不强制段落模板。
- 规则冲突时的优先级明确为：真实性 > 当前问题与用户明确要求（含语言）> Skill/自定义指令 > 默认风格。
- 语言规则：跟随用户明确要求，否则使用应用配置的回答语言；英文系统提示不代表要用英文回答。

## 新增（任务规定的边界，非针对题目）
- 报错题：有代码、报错或截图时，先修正再解释；缺少这些时要说明缺什么并索要，可列出标注为“未确认”的可能原因，不把猜测的修复当成修正。
- 不声称运行、编译或测试过代码。
- ACM 与 LeetCode 接口分开说明，ACM 要求处理跨行输入、不输出提示。
- 系统设计要先写必要假设，方案与假设相称，并写出何时需要改变设计；不编 QPS、不堆组件。
- 资料里写“未参与某事”时，不能扩大成关于整个项目的断言。

## 删除
- 销售、谈判、会议纪要、讨论引导、仓库示例、capture 输出形状、表情符号标签、“Nothing actionable right now.” 固定句等与软件面试无关的部分。
- 禁用词清单（delve、leverage 等）：属于英文风格噪音，与默认非英文回答关系不大；只保留破折号、分号和教练前缀规则。
- 原版中重复出现两三遍的同一规则（上下文隐身、反编造、上下文路由）。

## 不改变的接口语义
候选不涉及 Skill 选择、Local Context 隐私规则、普通/笔试入口、缓存或输出预算。测试时，语言后缀仍沿用此前脚本，在系统提示末尾追加 "Answer in Simplified Chinese."，与原版处理一致。候选中没有题号、模型名称或针对 20 道题的答案。
