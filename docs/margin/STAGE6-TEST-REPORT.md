## 3. 需要你人工做的测试

2026-11-01 按用户同意精简：只测核心场景用得到的项，外观、偏好、很少使用或已由自动测试覆盖的项不再人工测试，删除清单及理由见[清单的已删除项](STAGE6-CHECKLIST.md#已删除项)。不再做安装包或 asar 的 SHA256 核对。按这个顺序做，大约一场会议就能完成；每项对应清单编号。不通过的项写下现象，截图放到 `evidence/stage6-retest/`。

### 3.1 配置（约 5 分钟，产生极少费用）

1. 设置 → 语音与音频：选 Groq，填 Key，保存，测试连接成功。（B2）
2. 设置 → AI 服务商 → Gemini：填 Key，点"获取模型"，确认不会自动替你选第一个；把 `gemini-3.1-flash-lite` 和 `gemini-3.5-flash-lite` 加为已保存模型，"保存并测试"成功。（B2）
3. 顶部主模型选 `gemini-3.1-flash-lite`，备用模型选 `gemini-3.5-flash-lite`，主模型旁选一个推理档位。重启应用后都还在。（B2）

### 3.2 设置页快速走查（不调用服务，约 5 分钟）

- 各页面能切换；深浅色都看得清；中英切换后三个窗口变化。（A1、A2）
- 窗口保护、鼠标穿透开关可用；AI 服务商、语音与音频、上下文与技能三页能正常使用。（A4、A7）

### 3.3 真实会议和回答（清单 B1、B3、B4、A5、A6）

1. 冷启动到启动器出现，不卡；没有重复的权限提示。先在语音设置里清空 Groq，开始会议应该被拒绝并提示去配置；然后再配回来。（B1）
2. 开一场会议，自己说话，同时播放一段视频或会议录音：两路转写都出现，并且分得对。中途把系统静音一会儿，不应误报；恢复后系统音频转写正常。（B3）
3. 用快捷键依次试 What to Answer、Answer/Stop、截图提问、区域截图，再试文字发送；截图放大和屏幕对比清晰度。（B4、A6）
4. 笔试：截一道真实编程题，检查回答语言、提交框架、是否先给代码；再贴一段报错，看能否修复。（B4）
5. 遇到失败时点"重试"；Clarify、Brainstorm、Recap、Follow Up 任选一个点一次。（B4）
6. 结束会议：尾段转写收齐，会议记录里能看到这场，详情和复制可用。（B3、A5）

### 3.4 共享保护（清单 B5，最关键）

Mac 上用整屏共享，接收端是另一台电脑上的另一个账号。Zoom 和腾讯会议各做一遍：

1. 接收端看不到启动器、会中窗口、设置窗口，也没有黑框；你在 Mac 上照常能看到和操作。
2. 共享中关掉窗口保护，接收端应该能看到窗口；再打开后立即看不到。
3. 记录软件版本、共享方式、接收端看到的画面，最好拍一张接收端截图。

### 3.5 退出和再启动（清单 B6）

1. 会议进行中、辅助窗口开着时直接退出：**用一场可以丢弃的短会议来测**。退出成功，活动监视器里没有残留进程，也不再生成回答。退出时应用会尝试保存一次这场会议；保存失败的会议退出后丢失，目前不会跨重启恢复，所以先看有没有保存失败的提示，不要直接记成缺陷。
2. 再次启动后，之前的设置（包括主备模型和推理强度）都在，**此前已成功保存的**会议记录也都在。

### 3.6 本轮不测

设备切换（麦克风、耳机、蓝牙）、Chrome 和飞书共享、费用上限、备用模型自动切换、未使用的服务商和网关，以及[已删除项](STAGE6-CHECKLIST.md#已删除项)。Windows 见 Windows 开发分支的实机最小清单。

### 4.3 需要你授权后能做

- **用临时配置启动已安装的应用**：不碰你的数据。可以测冷启动耗时、退出后有没有残留进程，以及窗口保护的本机代理检查：用系统截屏和窗口列表，确认受保护的窗口没有被截进去。这只能说明 macOS 自带截屏的行为，Zoom 和腾讯会议的采集方式可能不同，所以**代替不了 3.4 的接收端检查**。

- **用你的真实配置操作应用**：需要你同意我读取真实界面和数据，而且你仍要在场处理权限弹窗。
